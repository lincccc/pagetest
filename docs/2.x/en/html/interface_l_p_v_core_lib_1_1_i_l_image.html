Detailed Description

This interface expose APIs to access/manipulate/draw a LPV LImage object.

Image is the core object in a vision system. The image class encapsulate all the functionality needed to represent a rectangular shaped image. It stores pixels as a 2-dimensional dense array, row by row.

To use this interface, you should create a LImage object.

There are many different ways to initialize data of the image. The most popular options are listed below:

  1. Load image from file via ILImage::Load().
  2. Set image data for data pointer via ILImage::SetImageData(), typically you may get this pointer from camera's callback function.
  3. Set image size as wanted, then assign pixel values one by one manually. But please noted, this way is not efficient.

Example Code

C++
// 1. load from file
img->Load(L"img.bmp");
// 2. load from data pointer
img->SetImageData(width, height, dataPtr, bytesPerLine, true);
// 3. set pixels manually
img->SetSize(100, 100);
img->PutPixel(10, 20, 255); // set (10, 20) to be a white pixel
C#
// 1. load from file
img.Load("img.bmp");
// 2. load from data pointer
img.SetImageData(width, height, dataPtr, bytesPerLine, true);
// 3. set pixels manually
img.SetSize(100, 100);
img.Pixel[10, 20] = 255; // set (10, 20) to be a white pixel
COM
// 1. load from file
img->Load(L"img.bmp");
// 2. load from data pointer
img->SetImageData(width, height, dataPtr, bytesPerLine, true);
// 3. set pixels manually
img->SetSize(100, 100);
img->Pixel[10][20] = 255; // set (10, 20) to be a white pixel

◆ ReorderChannel()

ILImage* ReorderChannel ( int  idx0,
int  idx1,
int  idx2 
)

Reorder the channels of a multi-channel image and return the new image. The current image is not modified. idx0, idx1 and idx2 give the source channel index for the channels of the result image, where the 3rd one is used only by a 3-channel image. idx1 and idx2 default to -1, which means keeping the corresponding channel of the current image at the same position, ie. no change for that channel. The result image is of the same size, format and depth as the current image.

Take a BGR color image for example:

  • ReorderChannel(2, 1, 0) returns a RGB image, ie. BGR -> RGB
  • ReorderChannel(1, 2, 0) returns a GRB image, ie. BGR -> GRB, the 0th channel is moved to the 2nd one, the 1st one to the 0th one and the 2nd one to the 1st one
  • ReorderChannel(2) returns an image whose 0th channel comes from the 2nd one while the other channels stay

For a 2-channel image (like ), only idx0 and idx1 are used and idx2 is ignored. A duplicate index is allowed, like ReorderChannel(0, 0, 0) assigns the 0th channel to all of them. This function is invalid for a single channel image and returns an invalid-argument error.

Parameters
[in]idx0The source channel index for the 1st channel of the result image, mandatory, 0 or more and less than the channel count of the current image.
[in]idx1The source channel index for the 2nd channel of the result image. Negative means no change.
[in]idx2The source channel index for the 3rd channel of the result image. Negative means no change.
Return values
resultImageReturn the new image of the reordered channels. It's of the same size, format and depth as the current image.
Since
2.23.0

◆ SaveWithFormat()

LPVErrorCode SaveWithFormat ( LString  filename,
LString  format,
ILRegion *  region 
)

Save the image object to a specified file. The format is given in the pass-in format argument. Currently, we support the following formats.

FormatUsage
bmpWindows-BMP format
  • can only store 8bit images with 1 channel (gray) or 3 channels (RGB color).
jpegJPEG format - lossy compression
  • can only store 8bit images with 1 channel (gray) or 3 channels (RGB color).
  • pass in together with the quality value for compression rate, in 0 ~ 100, like "jpeg 60". By default, it's 95.
pngPNG format - lossless compression
  • can only store 8bit images with 1 channel (gray) or 3 channels (RGB color).
  • pass in together with the quality value for compression level 0 ~ 9, like "png 6", where 0 corresponds to no compression and 9 to the best possible compression.
tiffTIFF format - lossless compression
  • all image format are supported to store.
webpWEBP format - lossless or lossy compression
  • can only store 8bit images with 1 channel (gray) or 3 channels (RGB color).
  • pass in together with the quality value for compression rate, in 0 ~ 100, like "webp 60".
Parameters
[in]formatGraphic format.
[in]regionOptional, could be null. If you want to only save part of the image, pass in a region.
[in]filenameFull path of the file, it could be absolute or relative path with file name and extension.
Return values
errorReturn error code if anything is wrong.
See also
Save(), Load()

◆ SetImageData()

void SetImageData ( int  w,
int  h,
LPVOID  dataPtr,
int  bpl,
BOOL  copyData 
)

Assign data to the image object via an external allocated buffer.
If copyData is set to False, this pointer overwrite the internally allocated buffer inside the image object. You should take the responsibility to keep the buffer alive during the entire life cycle of the image object.
If copyData is set to True, we'll copy the content into the buffer owned by the image object. You don't need to worry about the data life cycle then.

Parameters
[in]wThe width of the image in pixels, should be a positive value.
[in]hThe height of the image in pixels, should be a positive value.
[in]dataPtrPointer to the external image data buffer.
[in]bplBytes per line, the number of bytes contained in a row. The value should include the padding bytes. at the end of each row, if any. If set to 0, no padding is assumed and the actual stride is calculated as column number * pixel size(sizeof(char)).
[in]copyDataWhether to copy the data into owned buffer of the image object.

◆ ImageFormat

LPVImageFormat ImageFormat
getset

The format of the image.

For non-empty image, if you change the image format, we'll do a simple image type conversion to match the new format.
Generally, it converts pixel values to the target data type with no scaling, clamps to avoid possible overflows. If the target has more than 1 channels, assign the same value to all channels. The exceptions are as follows:

From To Conversion
U8C1 U8C3 Converts grayscale to BGR color, all 3 channels are assigned to the same value, same as GrayToBGR()
U8C3 U8C1 Converts BGR color to grayscale, same as BGRToGray()
U8C3 U16C1 / S32C1 / F32C1 / F32C2 Converts firstly to grayscale as BGRToGray(), then do the general conversion
F32C2 U8C1 / U8C3 / U16C1 / S32C1 / F32C1 Calcuates pixels' magnitude based on the real and imaginary parts, apply the natural logarithm to the result, then do the general conversion
